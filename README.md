# 智慧园区

基于 React、TypeScript 和 Vite 的智慧园区管理后台，面向单园区日常运营场景，提供企业、人员、访客、车辆、工单、设备及系统管理功能。

项目是可交互的前端演示系统，所有业务接口由浏览器端 MSW 模拟，不依赖真实后端，也不连接数据库、门禁、停车设备或第三方平台。业务修改保存在当前浏览器中，可用于产品演示、交互验证和前端开发参考。登录、角色权限及数据范围校验均为模拟实现，不作为生产级安全方案。

## 环境准备

- Node.js `>=24.18.0`、pnpm `>=11.13.0`。
- 包管理器：`pnpm@11.13.0`。

## 演示账号

| 角色     | 账号           | 初始密码             | 初始数据范围 |
|--------|--------------|------------------|--------|
| 超级管理员  | `admin`      | `Admin@123`      | 全部数据   |
| 园区运营人员 | `operator`   | `Operator@123`   | 当前园区   |
| 企业用户   | `enterprise` | `Enterprise@123` | 所属企业   |

- 超级管理员可体验全部业务、用户与角色管理、操作日志和 Mock 数据管理。
- 园区运营人员主要维护业务档案、审批访客预约并处理工单。
- 企业用户主要查看所属企业数据、创建访客预约和工单，并确认工单处理结果。

> 模拟会话有效期为两小时。

| 车辆与停车     | 车辆档案维护、启停及停车记录查询             |
| 工单中心      | 创建、受理分派、处理、确认评价、取消、重新打开及流程记录 |

企业、车辆、设备列表支持跨页勾选并导出已选记录为 `.xlsx` 文件。

### 推荐体验流程

**访客预约与到访**

1. 使用 `enterprise` 登录，在访客预约中创建预约，选择本企业的在职受访人员
2. 预约开始时间需晚于当前时间，结束时间需晚于开始时间
3. 退出后使用 `operator` 登录，审批该预约，再执行签到和签出
4. 查看到访记录，核对预约信息与实际到访时间

已批准但超过预约结束时间且未签到的预约，会在接口读取时更新为已过期。
建议新建预约体验完整流程，避免历史种子数据因日期变化而过期。

**工单处理与确认**

1. 使用 `enterprise` 创建工单，填写问题信息，可添加现场图片
2. 切换到 `operator`，受理并分派给当前运营账号
3. 由处理账号开始处理、提交处理结果
4. 切回 `enterprise`，确认完成并可填写评分
5. 查看工单详情中的处理记录、状态进度和评价

处理结果仅允许当前处理人或具备管理员权限的账号提交，确认人不能是当前处理人。
现场图片通过模拟上传接口保存于浏览器数据中，不会上传到真实文件服务。

**权限与异常状态**

使用 `admin` 在系统管理中新增角色、配置页面和操作权限，再分配给演示用户，
体验菜单、按钮和接口权限的变化。内置角色不可删除，超级管理员角色及权限不可修改；
自定义角色仍有关联用户时不可删除。

在 Mock 数据管理中调整响应延迟或启用模块异常，观察加载、错误提示及鉴权跳转。
模拟结束后关闭异常，或恢复初始数据。

## Mock 数据与环境配置

### 请求与持久化

应用先启动 MSW，再加载业务模块，保证动态菜单等初始化请求能被模拟接口处理。
页面通过 `src/api/` 中的请求函数访问统一 HTTP 层，不直接读取 Mock 种子数据。

可修改业务数据、角色授权记录、模拟会话及 Mock 配置通过 `localStorage` 保存。
刷新页面后仍会保留；浏览器配置及访问来源（协议、域名、端口）不同，数据相互隔离，
不会共享到其他浏览器或真实服务。部分统计及历史记录来自种子数据或接口计算，
不代表真实园区的实时数据。

Mock 管理入口为 `/system/mock-data`，需要 `mock-data:manage` 权限：

- 响应延迟范围为 `0～2000ms`，默认 `300ms`
- 异常模拟覆盖登录、企业、访客、工单和设备模块，默认全部关闭
- 支持模拟 `400`、`401`、`403`、`404`、`408`、`429`、`500`、`502`、`503`、`504`
- Mock 管理及认证初始化接口不受模块异常拦截，便于恢复配置
- 恢复初始数据需二次确认，会重置业务修改、角色配置和授权记录、清除模拟会话，
  恢复默认 Mock 设置并记录最近恢复时间，随后返回登录页

Mock 数据管理不提供数据文件导入或导出；列表 Excel 导出是独立的业务功能。
若启用登录异常后无法登录，可在浏览器开发者工具中删除
`smart-park.mock-settings.v1` 这一项并刷新，使模拟配置恢复默认值。

### 环境变量

| 变量                | 默认或仓库配置        | 用途                       |
| ------------------- | --------------------- | -------------------------- |
| `VITE_ENABLE_MSW`   | 开发和生产均为 `true` | 仅字符串 `true` 会启用 MSW |
| `VITE_API_BASE_URL` | 未配置时为 `/api`     | Axios 请求基础地址         |

当前 `.env.development` 和 `.env.production` 都启用 MSW，生产构建仍是演示系统。
环境变量在 Vite 启动或构建时读取，修改后需要重启开发服务或重新构建。

接入真实后端时，应关闭 MSW、设置请求基础地址，并实现现有 API 所需的接口、
认证、菜单、权限及数据范围校验。关闭 MSW 本身不会提供后端能力。
Mock 处理器目前匹配 `/api/...`，启用 Mock 时应保留默认接口基础地址。

## 架构与扩展约定

### 路由与权限

认证接口返回当前账号可访问的菜单树，动态路由根据 `componentKey` 白名单映射到本地页面，
通过懒加载注册。企业详情和工单详情沿用对应列表的页面访问权限。
登录后默认进入第一个可访问菜单；没有业务菜单时进入个人中心。

权限分为菜单与页面访问、按钮操作、Mock 接口校验和业务数据范围过滤。
角色或用户授权变更后，通过权限同步 Hook 重新获取用户和菜单，并校验当前路由；
页面重新激活时也会同步。企业用户查询受所属企业范围限制。

### 接口与异常处理

业务请求统一放在 `src/api/`，请求函数以 `req` 开头。
HTTP 层自动携带 Bearer Token，统一响应结构为 `{ code, message, data }`，
`code: 0` 表示成功，调用方直接获得解包后的 `data`。
分页结构为 `{ list, total, page, pageSize }`，页码从 `1` 开始。

HTTP 层统一展示接口异常；非登录请求的 `401` 会清理会话并跳转登录页，
`403` 默认跳转无权限页。特殊交互可通过 `skipErrorMessage`、`skipAuthRedirect`
调整单次请求行为。业务代码使用 `async/await`、`try...catch`，
存在加载状态时由 `finally` 收尾，避免重复提示同一接口错误。

### 公共组件与页面扩展

- 列表页复用 `DataTablePageLayout`、`DataTablePanel`，由公共组件计算表体滚动高度，
  分页器固定在面板底部；默认每页 `20` 条，可选条数为 `20`、`50`、`100`
- 查询表单独立放在页面 `components/` 中，使用 Ant Design `Form`、`Row`、`Col`，
  列表级新增、导出等操作放在表格面板的 `toolbar` 中
- 长表单及详情弹窗使用 `ScrollableModal`，固定标题与底部操作，仅内容区滚动
- 跨模块导入使用已配置的 `@/` 别名，组件视觉样式使用邻近的 SCSS 文件

新增业务页面通常按以下顺序扩展：

1. 在 `src/types/` 定义带业务注释的请求、响应及 DTO
2. 在 `src/api/` 添加 `req` 请求函数
3. 在 `src/mocks/data/`、`src/mocks/handlers/` 添加数据和接口，并注册到处理器集合
4. 在 `src/pages/` 实现页面、独立筛选组件及 SCSS，按需复用公共组件
5. 在权限类型、权限目录及角色种子配置中补充所需权限点
6. 在 Mock 菜单树中添加菜单，并在 `src/router/dynamic-routes.ts` 注册组件映射
7. 检查角色可见性、按钮权限、直接访问路由、接口数据范围和异常状态

需要持久化的新数据同步维护 `src/mocks/store.ts` 的初始状态、兼容读取和重置逻辑。
详细开发要求见 [AGENTS.md](./AGENTS.md)。

## 构建与部署

```sh
pnpm build
pnpm preview
```

将 `dist/` 部署到静态站点服务。`pnpm preview` 用于本地检查构建产物，
部署时由所选静态站点服务提供文件。

- 使用 Browser Router，服务器需将 `/enterprises`、`/work-orders/:id` 等前端路由
  回退到 `index.html`，确保直接访问或刷新详情页可用
- 静态资源、`mockServiceWorker.js` 和真实 `/api/` 请求应优先匹配自身规则，
  不应返回 SPA 回退页面
- 演示模式必须发布构建产物中的 `mockServiceWorker.js`，并以 JavaScript 内容类型提供
- MSW 依赖 Service Worker，线上访问使用 HTTPS；本地可使用 `localhost`
- 当前配置按域名根路径部署，未配置路由 `basename`；部署到子路径时，
  需同步调整 Vite `base`、路由及相关资源路径，并验证 Worker 注册与页面刷新
