# 智慧园区管理后台产品需求文档

> 文档版本：V1.1（精简版）
>
> 文档状态：需求初稿，首期范围已确认
>
> 更新日期：2026-09-19
>
> 适用端：园区运营管理 Web 后台

## 1. 项目说明

“智慧园区”是一个面向园区日常运营的管理后台，主要用于展示和管理园区、企业、人员、访客、车辆、工单及设备数据。

项目定位为可完整操作的前端演示系统，不建设真实后端：

- 所有业务数据和 HTTP 接口均由 MSW Mock
- 不连接真实数据库、硬件设备或第三方平台
- Mock 数据保存在当前浏览器中，可恢复为初始数据
- 登录和权限仅用于演示，不作为生产级安全方案
- 首期按单园区场景设计，不处理复杂的多园区 SaaS 能力

## 2. 产品目标

### 2.1 核心目标

- 通过工作台快速了解园区当前运营情况
- 集中维护企业、人员、访客和车辆信息
- 演示访客预约与工单处理两个核心业务闭环
- 展示停车记录、设备状态等智慧园区典型数据
- 通过三个固定角色演示不同的数据和操作权限
- 使用 MSW 支撑所有列表、表单和状态流转

### 2.2 首期不做

- 招商、租赁、合同和收费结算
- 水电能耗分析、碳排放管理
- 设备巡检、维保计划和物资库存
- 消防告警、应急指挥和视频监控
- 公告、短信、企业 IM 等消息平台
- 自定义角色、复杂组织架构和复杂审批流
- 真实文件上传、支付、地图、门禁和停车设备控制
- 独立 App、小程序或企业用户门户

## 3. 用户角色

系统只保留以下三个固定角色：

| 角色 | 使用人群 | 数据范围 | 主要权限 |
| --- | --- | --- | --- |
| 超级管理员 | 系统维护人员 | 全部数据 | 全部业务操作、用户管理、Mock 数据管理 |
| 园区运营人员 | 园区前台、物业及运营人员 | 当前园区 | 企业、人员、访客、车辆、工单和设备管理 |
| 企业用户 | 入驻企业员工 | 所属企业 | 查看本企业信息、提交访客预约和工单 |

### 3.1 权限规则

- 角色为系统固定值，不提供角色新增、删除或权限编辑页面
- 超级管理员可创建用户、停用用户及分配角色
- 园区运营人员不能进入用户管理和 Mock 数据管理页面
- 企业用户只能查看所属企业数据，不能查看其他企业信息
- 无页面权限时进入 403 页面，未知地址进入 404 页面
- 页面按钮权限和 MSW 接口返回结果保持一致

## 5. 全局需求

### 5.1 后台布局

- 左侧显示当前角色可访问的菜单，支持折叠
- 顶部显示页面标题、消息占位入口和用户菜单
- 用户菜单包含当前账号、角色名称和退出登录
- 使用面包屑展示页面层级
- 默认进入运营总览

### 5.2 列表页

- 支持关键词和状态筛选
- 支持重置、分页和刷新
- 默认每页 20 条，支持切换每页数量
- 提供加载中、空数据、请求失败和无权限状态
- 删除、停用、取消等操作需要二次确认
- 从详情返回列表时保留筛选条件和页码

### 5.3 表单

- 明确标识必填项，并即时提示格式错误
- 页面与 MSW Handler 同时校验关键业务规则
- 提交时禁用重复点击
- 提交失败后保留已填写内容
- 离开未保存表单时进行确认提示

### 5.4 数据展示

- 状态使用统一的颜色和文字，不只依赖颜色区分
- 手机号、证件号码等敏感信息默认脱敏
- 时间统一展示为 `YYYY-MM-DD HH:mm:ss`
- 所有业务状态变化保留操作时间和操作人

## 6. 功能需求

### 6.1 登录

- 支持账号和密码登录
- 登录页展示三个角色的演示账号，便于快速体验
- 企业用户通过同一个登录页进入后台，并只能访问所属企业的数据和功能
- 支持正确账号、错误密码、账号停用三种结果
- 登录成功后进入运营总览
- 未登录访问业务页面时跳转至登录页
- 模拟 Token 过期后清除登录状态并返回登录页
- 支持主动退出登录

### 6.2 运营总览

展示以下内容：

- 指标卡片：入驻企业数、园区人员数、今日访客数、在场车辆数、待处理工单数、在线设备数
- 今日待办：待审批访客、待处理工单、异常设备
- 趋势图：近 7 日访客数量、近 7 日工单数量
- 设备状态：正常、故障、离线数量
- 快捷入口：新增企业、创建访客、创建工单

交互要求：

- 点击指标卡片进入对应列表，并自动带入筛选条件
- 每个数据区域独立处理加载失败
- 显示数据最后更新时间

### 6.3 园区档案

- 展示园区名称、地址、联系人、联系电话、占地面积和简介
- 展示楼宇数量、楼层数量、办公空间数量和已使用空间数量
- 使用简单树形结构展示楼宇、楼层和房间
- 超级管理员可编辑园区基本信息
- 首期仅维护一个园区，不提供园区新增、删除和切换功能

### 6.4 企业与人员

#### 6.4.1 企业管理

- 支持按企业名称和状态查询
- 维护企业名称、统一社会信用代码、行业、联系人、联系电话、入驻日期、办公位置和状态
- 企业状态包括已入驻、已停用
- 统一社会信用代码不可重复
- 企业停用后，不允许新增该企业人员、车辆或访客预约
- 企业详情展示基本信息、成员、车辆和关联工单

#### 6.4.2 人员管理

- 支持按姓名、手机号、所属企业和状态查询
- 维护姓名、手机号、证件类型、证件号码、工号、所属企业、部门和状态
- 证件号码完整保存在 Mock 数据中，列表默认脱敏，详情按权限展示
- 人员状态包括在职、离职、停用
- 人员离职或停用后，不允许作为受访人创建新预约
- 企业用户只能查看所属企业人员，不允许编辑其他企业数据

### 6.5 访客管理

#### 6.5.1 访客预约

- 维护访客姓名、手机号、受访人、访问事由、预约时间和车牌号
- 企业用户可为本企业创建访客预约
- 园区运营人员可创建预约，并且是唯一可执行访客审批的角色
- 支持通过、驳回、取消、签到和签出操作
- 驳回或取消时必须填写原因
- 已过预约结束时间且未签到的预约自动显示为已过期

预约状态：

`待审批 → 待到访 → 已到访 → 已离园`

终止状态包括已驳回、已取消、已过期。

#### 6.5.2 到访记录

- 展示访客、受访人、所属企业、预约时间、签到时间和签出时间
- 支持按访客姓名、企业、到访日期和状态查询
- 历史记录仅允许查看，不允许修改或删除

### 6.6 车辆与停车

#### 6.6.1 车辆档案

- 维护车牌号、车辆类型、车主、所属企业、联系电话和状态
- 车辆类型包括员工车、访客车
- 同一车牌只能存在一个有效档案
- 支持新增、编辑、启用和停用

#### 6.6.2 停车记录

- 展示车牌号、车辆类型、入口、入场时间、出口、出场时间和停留时长
- 支持查询当前在场车辆和历史停车记录
- MSW 预置正常进出、无权限入场和长时间未离场数据
- 停车记录仅允许查看，不提供收费和支付功能

### 6.7 工单中心

#### 6.7.1 工单创建

- 工单类型包括报修、保洁、投诉和其他
- 维护标题、描述、所属企业、企业联系人、位置、紧急程度和现场图片
- 图片使用浏览器内 Mock 上传接口，支持 JPG、PNG、WebP 及本地示例图片；最多 5 张，原图每张不超过 2 MB，上传前压缩并生成本地预览地址，不上传远端
- 企业用户可为本企业创建工单
- 园区运营人员可代为创建工单，但必须指定负责确认结果的企业联系人
- 系统生成唯一工单编号

#### 6.7.2 工单处理

- 园区运营人员可受理、分派、开始处理和提交处理结果
- 每次操作记录操作人、时间和备注
- 提交处理结果时必须填写处理说明，工单随后进入待确认状态
- 企业用户可确认工单完成，或提交 1～5 分评价及文字反馈；任一操作完成后工单进入已完成状态
- 园区运营人员不能代替企业用户确认自己处理的工单
- 超级管理员可取消或重新打开工单
- 列表点击查看进入 `/work-orders/:id` 独立详情页，展示基本资料、当前进度、现场图片、全部处理记录、企业确认和评价
- 尚未完成且未取消的工单可维护现场图片，归档后仅允许预览；图片及流程变更保存在浏览器 Mock 数据中，刷新后仍可展示

工单状态：

`待受理 → 待处理 → 处理中 → 待确认 → 已完成`

辅助状态为已取消。

### 6.8 设备管理

- 支持按设备名称、类型、位置和状态查询
- 维护设备编码、名称、类型、位置、责任人和状态
- 设备状态包括正常、故障、离线、停用
- 设备编码不可重复
- 设备详情展示基本信息和最近状态变化记录
- MSW 可定时随机改变部分设备状态，用于演示动态数据
- 不提供真实设备控制、巡检计划、维保计划和告警处置

### 6.9 系统管理

#### 6.9.1 用户管理

- 仅超级管理员可访问
- 维护用户名、姓名、所属企业、固定角色和状态
- 支持新增、编辑、启用、停用和重置模拟密码
- 用户名不可重复
- 超级管理员账号不能被停用或删除

#### 6.9.2 操作日志

- 记录登录、退出、新增、编辑、停用、审批和状态流转
- 展示操作人、操作时间、模块、动作、对象和结果
- 支持按操作人、模块和时间查询
- 日志由 MSW 生成，只允许查看

#### 6.9.3 Mock 数据管理

- 仅超级管理员可访问
- 展示当前 Mock 状态和最近重置时间
- 仅维护一套标准种子数据，不提供不同数据量的预置场景
- 支持设置统一接口延迟
- 支持临时指定接口返回失败，用于验证异常状态
- 支持恢复初始数据，操作前需要二次确认
- 不提供 Mock 数据导入和导出功能

## 7. 核心流程

### 7.1 访客流程

1. 企业用户或园区运营人员创建预约
2. 园区运营人员通过或驳回预约
3. 审批通过后进入待到访状态
4. 访客到达后由园区运营人员签到
5. 访客离开后签出，流程结束

### 7.2 工单流程

1. 企业用户或园区运营人员创建工单
2. 园区运营人员受理并分派
3. 处理人开始处理并填写过程备注
4. 处理人提交处理结果，工单进入待确认状态
5. 企业用户确认完成或提交评价
6. 工单进入已完成状态

## 8. MSW Mock 要求

### 8.1 接口规范

- 所有页面通过 `src/api` 中的请求函数访问数据
- 实际发送 HTTP 请求的函数名必须以 `req` 开头
- 页面和组件不得直接导入 Mock 数据
- Handler 按登录、企业、人员、访客、停车、工单、设备和系统模块拆分
- 列表接口统一支持分页、关键词和状态筛选
- 响应统一包含业务状态码、消息和数据
- 错误响应应提供可直接展示的错误信息

### 8.2 数据生命周期

- 首次启动时加载一套覆盖三个角色和主要流程的标准种子数据
- 新增、编辑和状态流转后更新 Mock 数据
- 使用 `localStorage` 保存演示过程中的数据变化
- 刷新页面后保留已修改数据
- 恢复初始数据时清除业务数据、模拟会话和操作日志
- Mock 数据只在当前浏览器生效，不模拟真实多人并发
- 不提供 Mock 数据文件的导入和导出接口

### 8.3 异常场景

MSW 至少支持以下可验证场景：

- 200：请求成功
- 400：表单或业务规则错误
- 401：未登录或模拟 Token 过期
- 403：无权限
- 404：数据不存在
- 500：模拟系统异常
- 请求延迟和请求超时

## 9. 数据规则

- 业务数据使用稳定且唯一的字符串 ID
- 企业、人员、车辆、工单和设备使用可搜索的业务编号
- 编号由 MSW Handler 统一生成，页面组件不自行生成
- 已产生业务记录的数据优先停用，不直接删除
- 历史记录保留当时的名称、企业和状态快照
- 所有 Mock 数据必须为明显的虚构信息，不使用真实个人信息
- 时间数据使用 ISO 8601 格式存储，在页面统一格式化展示

## 10. 非功能需求

### 10.1 性能与体验

- 普通 Mock 接口默认在 800 毫秒内返回
- 运营总览首屏在 3 秒内可用
- 页面切换时避免重复请求相同数据
- 单个接口失败不影响页面其他区域使用
- 页面刷新后能重新注册 Service Worker 并恢复数据

### 10.2 浏览器与响应式

- 支持最新版及前一个主要版本的 Chrome、Edge
- 主要适配 1280px 及以上桌面屏幕
- 低于推荐宽度时保证核心表格和表单仍可操作

### 10.3 演示数据安全

- 不保存或展示真实账号、密码、手机号、证件号码和车牌
- 登录、角色和按钮权限只用于演示，不视为真实鉴权
- 文件上传仅生成本地预览和模拟地址，不上传远端
- 页面需要避免 XSS 和不安全文件预览

## 11. 首期验收标准

- 三个角色均可使用演示账号登录，并看到各自有权限的菜单和数据
- 超级管理员是唯一管理员角色，另外两个角色名称不包含“管理员”
- 园区、企业、人员、车辆和设备数据可通过 MSW 完成查询和维护
- 访客预约可完整完成创建、审批、签到和签出
- 工单可完整完成创建、受理、处理、企业用户确认或评价
- 工作台指标与业务列表数据一致，并能下钻到对应页面
- 列表和表单具备加载、空数据、失败、无权限和校验状态
- 修改数据后刷新页面仍然保留，且可恢复为初始数据
- 全部业务请求由 MSW 拦截，不依赖真实后端或第三方服务
- 项目可在约定浏览器中正常构建和运行

## 12. 后续版本候选

以下功能仅在首期稳定后按实际需要增加：

- 能耗统计
- 设备巡检和维保
- 告警中心
- 公告与消息
- 运营报表
- 招商、合同和收费
- 多园区切换

## 13. 已确认事项
